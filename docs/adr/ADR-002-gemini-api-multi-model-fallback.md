# ADR-002: AI 추천 엔진으로 Google Gemini API 사용 및 멀티 모델 폴백 전략

- **상태**: 수용됨 (Accepted)
- **날짜**: 2026-05-19
- **작성자**: minseo

---

## 배경 (Context)

리브(Riv)의 핵심 차별점은 **대화형 AI 추천**이다.
사용자와 최소 3회, 최대 5회 질문-응답을 주고받아 취향을 파악하고, 구체적인 책과 이유를 추천해야 한다.

이를 위해 LLM API가 필요하며, 다음 선택지를 검토했다:
1. **Google Gemini API** — 무료 티어 제공, 한국어 품질 우수, `gemini-2.5-flash` 등 최신 모델 접근 가능
2. **OpenAI GPT API** — 유료, 한국어 품질 양호하나 비용 부담
3. **Claude API (Anthropic)** — 품질 우수하나 무료 티어 제한적
4. **로컬 규칙 기반 추천** — AI 없이 장르/이력 매칭만으로 구현하는 방식, 개인화 품질 낮음

대화 흐름에서 특정 모델이 과부하(429) 또는 서비스 불가(503) 상태일 경우 추천 화면이 완전히 멈추는 문제를 예방해야 한다.

---

## 결정 (Decision)

**Google Gemini API를 AI 추천 엔진으로 사용하고, 모델 우선순위를 정해 순차적으로 폴백한다.**

모델 우선순위:
1. `gemini-2.5-flash` (1순위 — 최신, 빠름)
2. `gemini-flash-latest` (2순위)
3. `gemini-2.0-flash-lite` (3순위 — 경량, 폴백용)

- HTTP 429(Rate Limit), 503(서비스 불가) 응답 시 다음 모델로 자동 전환한다.
- 다른 오류(400, 401 등)는 즉시 throw해 원인을 노출한다.
- API 키가 설정되지 않은 경우 **목 응답(getMockResponse)** 을 반환해 개발 환경에서도 전체 대화 흐름을 테스트할 수 있게 한다.
- 시스템 프롬프트에 `<SUGGESTIONS>` 태그 규칙을 포함해 AI가 버튼형 선택지를 구조화된 형태로 출력하도록 강제한다.

---

## 결과 (Consequences)

**긍정적 효과**
- 단일 모델 장애 시에도 추천 기능이 중단되지 않아 서비스 안정성이 높아진다.
- 무료 티어로 MVP 운영이 가능해 초기 비용이 0원이다.
- 목 응답 덕분에 API 키 없이도 로컬에서 전체 대화 흐름을 개발·테스트할 수 있다.

**부정적 효과 및 트레이드오프**
- API 키가 클라이언트 번들에 포함되어 노출 위험이 있다 (MVP 한계 — 배포 전 서버 프록시 전환 필요).
- 모델별 응답 품질·속도 차이로 사용자 경험이 일관되지 않을 수 있다.
- `<SUGGESTIONS>` 파싱은 AI 출력 형식에 의존하므로 프롬프트 변경 시 파서도 함께 검토해야 한다.

**향후 고려사항**
- 배포 단계에서 API 키를 백엔드 프록시로 이전해 클라이언트 노출을 제거한다.
- 추천 품질 개선이 필요하면 사용자 이력(최근 본 책, 구매한 책)을 시스템 프롬프트에 동적으로 주입하는 방식을 도입한다.
