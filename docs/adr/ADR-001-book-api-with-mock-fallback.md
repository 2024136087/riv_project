# ADR-001: 도서 정보 소스로 국립중앙도서관 오픈 API 사용 및 목 데이터 폴백 전략

- **상태**: 수용됨 (Accepted)
- **날짜**: 2026-05-19
- **작성자**: minseo

---

## 배경 (Context)

리브(Riv) 앱은 도서 제목, 저자, 장르 정보, 표지 이미지 등 풍부한 도서 메타데이터가 필요하다.
도서 데이터를 직접 수집·관리하면 초기 구축 비용과 유지보수 부담이 크다.
또한 MVP 개발 기간이 짧기 때문에 빠르게 실데이터를 확보할 수 있는 방법이 필요하다.

후보로 검토한 선택지:
1. **국립중앙도서관 오픈 API** (`data4library.kr`) — 공공 데이터, 무료, 장르(KDC) 기반 분류 지원
2. **알라딘/교보문고 API** — 유료 계약 필요, MVP 단계에서 접근 장벽이 높음
3. **직접 DB 구축** — 시간·비용 과다, 최신 도서 유지 어려움

---

## 결정 (Decision)

**국립중앙도서관 오픈 API(`data4library.kr`)를 1차 데이터 소스로 사용한다.**

- 도서 검색(`srchBooks`), 대출 인기 도서(`loanItemSrch`), 장르(KDC) 기반 조회를 API로 처리한다.
- API 호출 실패 또는 빈 응답 시 앱 내 **목 데이터(MOCK_BOOKS)** 를 폴백으로 반환한다.
- 목 데이터는 실제 ISBN·제목·저자가 있는 8권의 대표 도서로 구성해 개발·테스트 환경에서도 화면이 비지 않도록 한다.
- API 응답 형태(`doc` 오브젝트)는 공통 `Book` 타입으로 변환(`mapDoc`)해 상위 레이어가 데이터 소스를 의식하지 않도록 분리한다.

---

## 결과 (Consequences)

**긍정적 효과**
- 추가 비용 없이 수십만 권의 도서 메타데이터를 즉시 활용할 수 있다.
- KDC(한국십진분류법) 코드를 그대로 사용해 장르 페이지 구현이 단순해진다.
- 목 데이터 폴백 덕분에 오프라인·API 장애 상황에서도 기본 화면이 동작한다.

**부정적 효과 및 트레이드오프**
- 표지 이미지 URL이 없는 도서가 많아 썸네일 품질이 불균일할 수 있다.
- 공공 API 응답 속도가 느릴 경우 2초 이내 응답 목표를 달성하기 어렵다.
- API 스펙 변경 시 `mapDoc` 함수를 수정해야 한다.

**향후 고려사항**
- 응답 캐싱 도입으로 반복 요청 지연을 줄일 수 있다.
- 이미지 품질 개선이 필요하면 ISBN 기반으로 카카오 도서 API와 병행 조회하는 방안을 검토한다.
