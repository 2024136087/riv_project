# ADR-003: 사용자 데이터 저장소로 AsyncStorage 기반 로컬 퍼시스턴스 선택

- **상태**: 수용됨 (Accepted)
- **날짜**: 2026-05-19
- **작성자**: minseo

---

## 배경 (Context)

리브(Riv)는 사용자별로 다음 데이터를 저장해야 한다:
- 사용자 정보 (이름, 이메일)
- 최근 본 책 (최대 20권)
- 구매한 책 목록
- 보유 캐시(잔액)
- 등록된 결제 카드 목록

이 데이터를 어디에 어떻게 저장할지 결정해야 한다.

후보로 검토한 선택지:
1. **AsyncStorage (로컬)** — React Native 표준 키-값 저장소, 별도 서버 불필요
2. **백엔드 API + 원격 DB** — 영속성·멀티 기기 동기화 가능하나 서버 구축 비용 발생
3. **Firebase Firestore** — 서버리스 DB이나 설정 복잡도 있고 외부 의존성 추가
4. **SQLite (expo-sqlite)** — 관계형 데이터에 적합하나 현재 데이터 규모에서 과도한 설정

---

## 결정 (Decision)

**MVP 단계에서는 `@react-native-async-storage/async-storage`를 단일 퍼시스턴스 레이어로 사용한다.**

- 모든 저장 로직은 `src/services/storage.ts` 한 파일에 집중해 상위 레이어가 저장 방식을 의식하지 않도록 한다.
- 키 이름은 `riv_` 접두사를 붙여 다른 라이브러리 키와 충돌을 방지한다.
- 최근 본 책은 최신순으로 정렬하고 20권으로 상한을 두어 저장 공간을 관리한다.
- 구매한 책은 ISBN을 기준으로 중복을 방지한다.

---

## 결과 (Consequences)

**긍정적 효과**
- 서버 없이 전체 기능을 구현할 수 있어 MVP 개발 속도가 빠르다.
- 네트워크 없이도 사용자 이력이 유지된다.
- 코드가 단순하고 테스트하기 쉽다.

**부정적 효과 및 트레이드오프**
- 기기를 바꾸거나 앱을 삭제하면 데이터가 사라진다 (멀티 기기 동기화 불가).
- 민감 정보(카드 정보, 사용자 이메일)가 암호화 없이 기기 로컬에 저장된다.
- 사용자 이력이 서버에 없으므로 AI 추천 시 서버 측 분석을 활용할 수 없다.

**향후 고려사항**
- 배포 단계에서는 카드 정보 등 민감 데이터를 `expo-secure-store`로 이전하거나 백엔드로 위임한다.
- 사용자 이력 기반 추천 고도화가 필요할 때 백엔드 API 레이어를 추가하되, `storage.ts` 인터페이스를 유지하면 상위 레이어 변경을 최소화할 수 있다.
